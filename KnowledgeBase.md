# GameDev Text LLM — Изначальная База Знаний

## A) KnowledgeBaseIndex (человеческим языком)
- **Жанры и сеттинги:** быстрые конспекты для shooter, soulslike, roguelike, cozy, мобайл и др. Нужны для выбора тона, темпа и рисков.
- **Core loops и метапрогрессия:** краткие циклы действий + награды/ресурсы. Помогают отвечать про темп игры и удержание.
- **Механики и баланс-формулы:** стамина, крит-урон, экономия крафта, шумы. Используются, когда просят числа или правила.
- **Паттерны уровней/биомов:** схемы арен, коридоров, пазлов, биомов. Нужны, чтобы быстро выдать структуру уровня.
- **Контент и нарратив:** персонажи, боссы, лут, реплики, достижения. Покрывает запросы на лор и flavor.
- **Шаблоны UI/UX и систем:** пропуски, инвентарь, телеметрия. Ускоряют ответы по флоу и интерфейсу.
- **Кодовые заготовки под UE/мобайл:** псевдо-Blueprint, C++ паттерны, оптимизации. Помогают в режиме Coder.
- **Типовые баги/фиксы и QA-чеклисты:** что проверять на разных стадиях, регрессии, риски. Нужно для проверок качества.

## B) KnowledgeBaseData (JSONL-пакет)
- **Файл:** `knowledge_base.jsonl` — 61 строка, каждый объект вида:
  ```json
  {
    "type": "design|mechanic|level|content|code|qa",
    "stage": "concept|prototype|graybox|polish|release",
    "input": "...краткий запрос...",
    "output": "...готовый ответ...",
    "tags": ["genre:...", "engine:...", "difficulty:..."]
  }
  ```
- **Покрытие:** Unreal / русский приоритет, жанры shooter, soulslike, roguelike, cozy, VR, puzzle, tactics, mobile и др; сложности casual/mid/hard; стадии от concept до release.
- **Примеры строк:**
  ```json
  {"type":"design","stage":"concept","input":"Сформулируй core loop для аркадного раннера в киберпанке на UE5.","output":"Игрок бежит по неону, уклоняется свайпами, собирает батареи, каждые 30 с босс-дрон; лут конвертируется в апгрейды скорости и щита.","tags":["genre:runner","engine:ue5","difficulty:casual"]}
  {"type":"mechanic","stage":"graybox","input":"Сделай систему шумов для стелса.","output":"Каждый источник имеет радиус и длительность; враги переходят в поиск при превышении порога 60; пол — мягкий/твёрдый, модификаторы +10/+25.","tags":["genre:stealth","engine:ue5","difficulty:mid"]}
  {"type":"code","stage":"graybox","input":"Шаблон C++ UE для спавна волны врагов.","output":"Timer вызывает SpawnWave(); в функции создаём массив спавнпоинтов, берем N случайных, вызываем GetWorld()->SpawnActor<EnemyClass>(Transform); увеличиваем WaveIndex.","tags":["genre:shooter","engine:ue5","difficulty:mid"]}
  ```
- **Стиль:** ответы в БД не сжимаем — держим конкретику, числа и шаги, чтобы модель училась развернутому формату.

## C) Правила обновления БД
- Любая новая информация или правка от пользователя → новая строка в `knowledge_base.jsonl` с меткой `spec_delta` в `output` или отдельным тегом.
- Старые строки не удаляем; если устарело — добавляем тег `deprecated` и ссылку `superseded_by:<id>` на новую строку.
- Источники: только собственные/сгенерированные данные или совместимые лицензии (Apache/MIT/CC-BY); без внешних закрытых ссылок.
- `/patch` команды добавляют изменения, которые сразу логируются как новая запись с полями `stage`, `engine`, `genre`, `quality_tags` (если есть) для дальнейшего SFT.
- Для LoRA/SFT берём все строки, фильтруем по тегам (жанр/движок) под конкретный спринт, валидируем JSON перед обучением.
